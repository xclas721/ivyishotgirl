# 個人版 2.0 — UI/UX 設計規格

> **定位**：B（個人／小團隊帳本 2.0）  
> **日期**：2026-08-03  
> **狀態**：設計定稿 · **尚未實作**（實作請用本機一般 Agent 模式，勿用雲端模式直接開工）  
> **業務真相**：[`parallel-dev-plan.md`](./parallel-dev-plan.md) §3  
> **視覺**：沿用現有 marble／frosted glass／copper；本文件以 **UX／IA** 為主

---

## 0. 設計目標（一句話）

讓使用者在 3 秒內分清「我在看哪一季**收款**」與「公司這波要**發**多少」，並在同一個視覺語言下完成入帳、核對、查算三件事。

---

## 1. 現況診斷（為何要改 UX）

### 1.1 已驗證可用、應保留

| 能力 | 為什麼留 |
|------|----------|
| 貼 URL → 抓報價 → 入帳 | 核心工作流已順 |
| 收款季度篩選驅動列表／總覽／CSV | 語意正確（8 月開站＝Q3） |
| 公司發放波次獨立統計（5／8／11／2） | 業務正確 |
| 手機卡片／桌面表 | RWD 方向對 |
| 模糊搜尋、再同步、改密、側欄 drawer | 個人版夠用 |
| marble + glass + copper | 品牌識別，UI 可沿用 |

### 1.2 必須改掉的 UX 問題

| # | 問題 | 使用者後果 |
|---|------|------------|
| 1 | **總覽**與**發放面板**疊在同一頁、同一「總覽」開關下 | 兩組數字都叫「發放」，以為 bug |
| 2 | 命名「發放篩選總覽」 | 「發放」被收款篩選佔用，與公司發放波次撞詞 |
| 3 | `LedgerTabs` 多選眼睛開關 | 不是導覽、是顯示開關；「回簽試算／發放實領」被藏成區塊 |
| 4 | Context bar 永遠掛「收款季度」 | 看發放波次時仍以為篩選控得了發放數字 |
| 5 | 表格欄位過密 | 核對時找不到「最終獎金／回簽／收款」三個關鍵欄 |
| 6 | 舊制 3.5%／新制倍率在列表幾乎不可見 | 同季內金額差很大時無法自解釋 |
| 7 | 入帳成功後只跳總覽 | 缺少「這一筆算多少」的即時確認 |

**根因**：兩個 bounded context（收款季視角 × 公司發放波次）被塞進同一個捲動頁，卻共用一套語彙。

## 2. 使用者與任務

### 2.1 主要使用者

- **Ivy／業務本人**：每月／每季入帳、對公司發放金額、抽查單筆怎麼算  
- **偶爾協助者**（同密碼）：查規則、調倍率、匯出 CSV  

不做多帳號隔離（那是定位 A）；本版假設「進得來的人看得到全部」。

### 2.2 Jobs to be Done（依頻率）

| 優先 | Job | 成功標準 |
|------|-----|----------|
| P0 | 貼報價入帳 | 30 秒內看到案件出現、最終獎金可讀 |
| P0 | 看「這一收款季」總獎金與列表 | 篩選語意清楚；數字與列表一致 |
| P0 | 核對「公司這波發放」金額 | 與收款季篩選**視覺與導覽完全分離** |
| P1 | 查單筆計算明細（舊制／新制／倍率） | 不進倍率頁也能看懂 |
| P1 | 搜尋／匯出目前可見集合 | 沿用現況行為 |
| P2 | 調季度倍率、讀規則摘要 | 獨立頁，不干擾帳本 |

## 3. 資訊架構（IA）

### 3.1 導覽（側欄）— 單選目的地，廢除多選區塊開關

```text
┌──────────────────────────┐
│  Ivy的獎金               │
├──────────────────────────┤
│  帳本          ← 預設    │  /          收款季視角
│  發放核對                │  /payout    公司波次視角（新頁）
│  季度倍率                │  /multipliers
│  獎金規則                │  /rules
├──────────────────────────┤
│  修改密碼 / 登出         │
└──────────────────────────┘
```

**廢除**：`總覽｜案件明細｜回簽試算｜發放實領` 多選 Eye tabs。

**遷移對照**：

| 舊 | 新 |
|----|----|
| 總覽 + 發放面板疊加 | 帳本內「本季總覽」；發放獨立成「發放核對」 |
| 案件明細 | 帳本頁下半永久顯示 |
| 回簽試算區塊 | 帳本「構成」抽屜／次要區塊，或規則頁附錄；**不**佔主導覽 |
| 發放實領區塊 | 合併進「發放核對」頁的季分布圖（可選） |

### 3.2 雙軸語彙鎖定（全產品同一字典）

| 用語 | 意思 | 出現場景 |
|------|------|----------|
| **收款季度** | 依收款月份切的財務季 | 帳本篩選、列表範圍、CSV |
| **本季收款總覽** | 上方篩選範圍內的合計 | 帳本頁（**禁止**再叫「發放篩選總覽」） |
| **公司發放月** | 5／8／11／2 | 發放核對頁標題 |
| **本波發放** | 該發放月對應收款季的案件合計 | 發放核對 KPI |
| **回簽月份／回簽季度** | 決定%與倍率 | 單筆明細、規則、倍率頁 |
| **最終獎金** | 可計算案件的 round 後金額 | KPI、列表主欄、明細 |

口訣（規則頁與空狀態可重複）：**算錢看回簽，歸戶看收款，領錢看公司發放月。**

## 4. 畫面規格

### 4.1 帳本 `/` — 收款季工作台

**一頁一件事**：在選定的**收款季度**裡，入帳與核對案件。

#### 佈局（桌面，上→下）

```text
┌─ Context strip ─────────────────────────────────────────┐
│  正在看 · 收款季度  2026-Q3（8–10 月）                   │
│  [◀] [2026-Q3 ▾] [▶]     本季最終獎金  $xxx,xxx   12 筆 │
└─────────────────────────────────────────────────────────┘

┌─ 快速入帳（可摺疊，預設展開）───────────────────────────┐
│  URL 列 × N · 客戶類型 · [抓取並入帳]                   │
└─────────────────────────────────────────────────────────┘

┌─ 本季收款總覽 ──────────────────────────────────────────┐
│  [最終獎金*] [未連稅合計] [含稅總計] [筆數]             │
│  *無法計算筆數以 inline warning 掛在獎金旁              │
│  [構成 ▾]  依回簽月份筆數（預設收合）                   │
└─────────────────────────────────────────────────────────┘

┌─ 案件 ──────────────────────────────────────────────────┐
│  搜尋…          [匯出 CSV] [再同步可見]                 │
│  桌面：精簡表｜手機：卡片                               │
└─────────────────────────────────────────────────────────┘
```

#### Context strip 規則

- **只**出現在帳本頁。  
- 控制：列表、本季總覽、搜尋範圍、CSV、再同步可見。  
- 預設＝今天所在財務季（8 月 → Q3）— **維持現規則**。  
- 右側只放 **一個** 主數字（本季最終獎金）+ 筆數；其餘 KPI 在下方總覽，避免雙重噪音。

#### 本季收款總覽

- 標題固定：**本季收款總覽**（對齊篩選語意）。  
- 「依回簽月份統計」改為 **構成** 手風琴，預設收合（降低首屏雜訊）。  
- **不**再並排放發放波次面板。

#### 入帳成功回饋（UX 重點）

1. Toast／狀態列：`已入帳 QT-xxx · 最終獎金 $x,xxx`（舊制加小標「舊制 3.5%」）。  
2. 列表高亮該筆並捲入視野（沿用 highlight）。  
3. **不要**強迫切區塊；若構成是收合的，保持收合。  
4. 失敗：明確區分「抓取失敗／重複更新／缺回簽」。

#### 案件列表欄位（桌面精簡）

**預設可見（建議 ≤7）**：

1. 案件編號  
2. 客戶  
3. 類型  
4. 回簽月  
5. 收款月  
6. **最終獎金**（強調）  
7. 操作（再同步／刪）

**收進列展開或右側明細抽屜**：未連稅、含稅、業務、倍率摘要、報價連結、警示。

手機卡片維持現狀結構，但卡片主數字必須是**最終獎金**；次行顯示「回簽 · 收款」。

#### 單筆明細抽屜（桌面／手機共用語意）

點列或卡片開啟：

```text
案件 QT-… · 客戶名
─────────────────
最終獎金     $8,000
計算制度     新制（回簽 2026-Q2）
公式預覽     未連稅 × 4% × 火箭2 × …
回簽月份     2026-06 → Q2
收款月份     2026-09 → 收款 Q3
歸入發放     2026-11 公司發放波
[開啟報價] [再同步] [刪除]
```

舊制列：`計算制度 舊制 3.5%（回簽 ≤2026-Q1）`，不顯示四倍率。

### 4.2 發放核對 `/payout` — 公司波次工作台（新頁）

**一頁一件事**：核對公司在某個發放月要發的那一波。

```text
┌─ Wave hero（非篩選條）──────────────────────────────────┐
│  公司發放 · 2026 年 8 月                                 │
│  對應收款季度 2026-Q2（5–7 月）                          │
│  [上一波]  [最近]  [下一波]                              │
└─────────────────────────────────────────────────────────┘

┌─ 本波發放 KPI ──────────────────────────────────────────┐
│  本波最終獎金* / 未連稅 / 含稅 / 筆數                    │
└─────────────────────────────────────────────────────────┘

┌─ 本波案件（可選，建議做）───────────────────────────────┐
│  僅此波收款季內案件；搜尋／匯出獨立於帳本篩選             │
└─────────────────────────────────────────────────────────┘

┌─ 發放曆（靜態說明，可摺疊）─────────────────────────────┐
│  Q1收款→5月發｜Q2→8月｜Q3→11月｜Q4→隔年2月             │
└─────────────────────────────────────────────────────────┘
```

#### 硬性規則

- **沒有**收款季度篩選器。  
- 波次切換**只**改本頁資料。  
- 從帳本點「查看對應發放波」可 deep-link：`/payout?wave=2026-08`（可選）。  
- 文案禁止再用「上季」當標題主詞（易與「上一財務季」混淆）；副標可用「相對今天的最近一波」。

#### 為何獨立成頁

| 疊在帳本 | 獨立頁 |
|----------|--------|
| 兩個 context 搶同一捲動 | 進頁＝換腦 |
| Context bar 誤導 | 無收款篩選 |
| 總覽開關綁死 | 導覽一層可達 |

---

### 4.3 季度倍率 `/multipliers`

- 沿用現頁；標題區加一句：**僅影響回簽 ≥2026-Q2 的新制案件**。  
- 舊制案件在明細抽屜寫死 3.5%，避免使用者以為改倍率會改到舊案。

### 4.4 獎金規則 `/rules`

- Hero 口訣置頂（品牌級、短）。  
- 三節固定順序：回簽怎麼算 → 收款怎麼歸戶 → 公司何時發。  
- 舊制／新制對照表各一，勿長文。

### 4.5 密碼閘／改密

- 視覺沿用；文案維持產品名 **Ivy的獎金**。  
- 個人版 2.0 不改 Auth 模型（仍共用閘）。

## 5. 關鍵流程（UX Flow）

### 5.1 入帳

```text
帳本 → 貼 URL + 選類型 → 抓取並入帳
  → 成功：Toast（編號＋最終獎金＋制度標籤）+ 列表高亮
  → 缺回簽：入帳成功但獎金顯示「無法計算」+ 引導補月份
  → 抓取失敗：URL 列 inline error，不關閉表單
```

### 5.2 看本季收款

```text
開站 → 預設本財務季 → 讀 Context strip 主數字
  → 需要細節：展開「構成」或往下看列表
  → 換季：只動帳本資料；發放核對頁不受影響
```

### 5.3 核對公司發放（8 月情境）

```text
側欄「發放核對」→ 預設「最近一波」＝8 月發＝Q2 收款
  → 讀「本波最終獎金」
  → 需要對名單：看本波案件表
  → 與帳本 Q3 數字不同 → 預期行為（設計如此）
```

**首次進入發放核對**（可選輕量）：一次 dismissible tip  
「這裡看的是公司發放波次，與帳本上方的收款季度無關。」

### 5.4 查單筆為什麼是這個數

```text
列表點列 → 明細抽屜 → 制度＋公式＋回簽／收款／對應發放月
  → 若新制：連到該回簽季倍率頁（深鏈可選）
```

## 6. 狀態設計

| 狀態 | 帳本 | 發放核對 |
|------|------|----------|
| 空（該範圍 0 筆） | 「這一收款季尚無案件」+ CTA 入帳 | 「這一波尚無對應收款案件」 |
| 載入中 | 骨架或既有 loading，避免整頁閃白 | 同左 |
| 部分無法計算 | KPI 旁 warning，不把整塊變紅 | 同左 |
| 離線／API | 沿用 DbStatusBanner | 同左 |
| 搜尋無結果 | 「無符合案件」保留篩選提示 | 同左 |

## 7. 響應式

| 斷點 | 行為 |
|------|------|
| ≤768px | 側欄 drawer（沿用）；Context／Wave hero 直向堆疊；列表＝卡片；明細＝bottom sheet |
| 769–1440 | 精簡表；明細＝右側 drawer（建議寬 ~360px） |
| >1440 | 同桌面；內容 max-width 沿用現有 layout token |

動畫：沿用既有 2–3 個有意義動效（頁切換、KPI 數字入場、高亮列）；手機維持簡化（不加重 blur）。

**可直接沿用**

- `main.css` 色票：`--color-copper`、marble 底、frosted `.panel`

**微調建議（可選）**

- 帳本 Context strip：左側銅線或小標「收款」色票

- 用色區隔 context，而不是新主題色系

## 10. 驗收（UX，非程式）

實作完成後，找沒看過內部討論的人問：

1. 8 月打開帳本，預設季是？→ 應答 Q3（收款）。  
2. 公司 8 月要發的錢去哪看？→ 應指向「發放核對」，且說出對應 Q2。  
3. 為什麼帳本數字 ≠ 發放核對數字？→ 應能說「一個看本季收款、一個看公司這一波」。  
4. 點一筆舊制案，能否看出是 3.5% 不是算不出來？  
5. 手機能否完成：入帳 → 看本季合計 → 切到發放核對看本波。

五題中 ≥4 題直覺答對，才算 UX 達標。

## 11. 實作邊界（給下一輪 Agent）

1. **本文件只定義 UX／IA／文案字典**；業務公式以 `parallel-dev-plan.md` §3 為準。  
2. **請在本機一般模式實作**；不要用雲端 Agent 一次改完整站（易與未合併 PR 打架）。  
3. 建議實作順序：  
   1. 導覽＋路由 `/payout`＋搬移發放面板  
   2. 更名「本季收款總覽」＋構成收合  
   3. 廢除 LedgerTabs 多選  
   4. 列表精簡＋明細抽屜  
   5. 入帳 Toast／制度標籤  
4. UI 元件可複用現有 Vue 元件，優先改結構與文案，而非重畫視覺系統。

## 12. 決策紀錄

| 決策 | 選擇 | 理由 |
|------|------|------|
| 產品定位 | **B 個人版 2.0** | 使用者指定；不做多帳號 |
| 發放 UX | **獨立頁** | 徹底切開兩個 context |
| 視覺 | **沿用 marble／copper** | 品牌已建立；問題在 UX 不在皮 |
| 區塊 Eye tabs | **移除** | 降低「顯示開關 ≠ 任務」的認知稅 |
| 回簽試算大區塊 | **降級** | P2；主路徑不需要整頁統計表 |

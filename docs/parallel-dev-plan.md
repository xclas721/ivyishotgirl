## 1. 為什麼要平行開發

| 現況個人版 | 平行版機會 |
|------------|------------|
| 業務規則已在使用中驗證清楚 | 可一開始就依正確領域模型設計 |

| UI／流程已有可抄的產品形狀 | 可保留流程，換更乾淨的技術邊界 |
| 與「方案 B 多帳號」規格混在同一 repo 敘事 | 平行版可乾淨切開：個人版繼續維護、正式版另起 |

**原則**：個人版可繼續小修；平行版**不 fork 亂改同一套狀態**，而是「業務規格共用、程式碼可重寫」。

## 3. 業務真相來源（已確認 · 2026-08）

下列規則已於個人版驗證並與產品方對齊；平行版**必須**實作一致（除非另開變更單改規格）。

### 3.1 兩個月份

| 欄位 | 意義 | 決定什麼 |
|------|------|----------|
| **回簽月份** | 案子回簽／簽約月 | **怎麼算獎金**（%／倍率） |
| **收款月份** | 案子收款入帳月 | **歸哪一個收款季度**、進哪一波公司發放 |

口訣：**算錢看回簽，歸戶／發放看收款。**

### 3.2 財務季度（回簽、收款共用切法）

| 季度 | 月份 |
|------|------|
| Q1 | 2–4 月 |
| Q2 | 5–7 月 |
| Q3 | 8–10 月 |
| Q4 | 11–12 月 + **隔年 1 月**（1 月屬前一年 Q4） |

### 3.3 獎金計算（依回簽季度）

**回簽 ≥ 2026-Q2（新制）：**

```text
最終獎金 = round( 未連稅金額 × 客戶類型基礎% × 業績火箭 × 回購 × 客單價 × 成材率 )
```

客戶類型基礎%：

| 類型 | % |
|------|---|
| 商業合作 `biz` | 2 |
| 廚具商 `kitchen` | 3 |
| 設計師 `designer` | 4 |
| 個人業主 `personal` | 5 |

四倍率：每「回簽季度」一組，未設定預設皆 `1`。

**回簽 ≤ 2026-Q1（舊制）：**

```text
最終獎金 = round( 未連稅金額 × 3.5% )
```

- 不分客戶類型  
- **不套**四倍率  
- 仍可計算並計入總計（不是「無法計算」）  
- 「無法計算」僅保留給**缺回簽月份**等無法定季的情況

### 3.4 公司發放波次（依收款季度）

| 收款月份落在 | 收款季度 | 公司發放月 |
|--------------|----------|------------|
| 2–4 月 | Q1 | **5** 月 |
| **5–7 月** | **Q2** | **8** 月 |
| 8–10 月 | Q3 | **11** 月 |
| 11–12 + 1 月 | Q4 | **隔年 2** 月 |

例：收款在 2026-05／06／07 → 收款季度 **2026-Q2** → 公司 **2026-08** 發這波獎金。

「上季獎金發放（8 月發放）」統計的是：**收款月份落在 Q2 的案件總獎金**，不是「收款月份＝8 月」。

### 3.5 畫面上三塊（勿混）

| UI | 資料範圍 | 備註 |
|----|----------|------|
| 上方「收款季度」篩選 | `收款月份` ∈ 選中財務季 | 預設＝**今天所在財務季**（8 月開站→**Q3**，正確） |
| 發放篩選總覽 | 同上篩選結果 | 合計 + 區間內各**回簽月份**筆數 |
| 上季獎金發放（X 月） | 該公司發放月對應的**收款季** | 與上方篩選**獨立**；可切換上一波／下一波 |

因此 8 月開站時：篩選預設 Q3、發放面板顯示「8 月發＝Q2」——**數字可以不同，這是設計不是 bug。**

### 3.6 跨季案（產品已接受）

| 回簽 | 收款 | 計算 | 歸戶 |
|------|------|------|------|
| 2026-03（Q1） | 2026-06（Q2） | 舊制 3.5% | 收款 Q2／8 月發放波 |

### 3.7 報價單與資料

- 來源：`quote.saiens.tw` URL → 後端抓 HTML → 解析未連稅、總計、回簽、案件編號、業務  
- 客戶類型：新增時使用者選；再同步**不覆寫**類型  
- 同一網址重複新增＝更新同一筆  
- CSV：匯出目前篩選可見集合；檔名含季度／時間／搜尋詞（個人版已有）

## 4. 從個人版學到、平行版要避開的坑

1. **篩選維度與發放波次混用** → 一開始就分開「收款季篩選」與「公司發放波次」兩個 bounded context。  
2. **舊制顯示「無法計算」** → 舊制是 3.5%，不是算不出來。  
3. **發放面板誤用 `paidMonth === 發放月`** → 必須是 `getFiscalQuarter(paidMonth) === 對應收款季`。  
4. **模組級全域狀態難測、難多帳號** → 平行版領域計算要純函式；UI 狀態用明確 store／context。  
5. **文件與程式漂移** → 平行版以「本計畫 §3」+ 自動測試為準；改規則先改測試與本文件。

## 5. 建議架構（平行版）

```text
┌─────────────────────────────────────────┐
│  Apps（個人 2.0 或 正式多帳號）          │
│  UI / Auth / 匯入匯出 / 報價抓取         │
└─────────────────┬───────────────────────┘
                  │
┌─────────────────▼───────────────────────┐
│  Domain core（建議先抽）                 │
│  · fiscalQuarter                         │
│  · commission（舊制 3.5% / 新制倍率）    │
│  · payoutSchedule（5/8/11/2 ↔ 收款季）   │
│  · filters（by paid quarter / search）   │
│  · 純函式 + 單元測試（必過）             │
└─────────────────┬───────────────────────┘
                  │
┌─────────────────▼───────────────────────┐
│  Persistence                             │
│  Supabase（或同等）+ RLS                 │
│  正式版：依角色／業務別名隔離            │
└─────────────────────────────────────────┘
```

**可從個人版直接搬、幾乎不用改語意的模組：**

- `fiscalQuarter.ts`、`payoutSchedule.ts`、`ledgerSummary` 計算核心、`customerType` 費率  
- 對應 Vitest（當回歸黃金樣本）

**建議重寫的部分：**

- `ledger.ts` 巨型模組狀態 → 明確 repository + use-cases  
- Auth（個人閘 vs 多帳號）  
- 若做正式版：RLS、別名、管理頁（依 `spec/…` 與 `需求清單.md`）

## 6. 開發階段（建議順序）

### Phase 0 — 定案（0.5～1 天）

- [ ] 勾選 §2 產品定位（A／B／C）  
- [ ] 決定 repo：同 org 新 repo，或 monorepo packages  
- [ ] 決定是否沿用同一 Supabase project（**建議正式版另開**，避免搞壞個人版資料）

### Phase 1 — 領域核心（優先）

- [ ] 建立 `packages/bonus-domain`（名稱自訂）  
- [ ] 移植並鎖死 §3 規則的單元測試（含：舊制 3.5%、8 月發＝Q2 收款、1 月∈前一年 Q4、跨季案）  
- [ ] 匯出型別：`BonusRecord`、`QuarterMultiplier`、`PayoutWave`  
- [ ] **完成定義**：不依賴 Vue／DB，Node 下 `vitest` 全綠

### Phase 2 — 垂直切片 MVP

最小可用路徑：

1. 登入（個人閘或正式 Auth，二選一）  
2. 貼 URL 抓報價（可先 mock parser）  
3. 列表 + 收款季度篩選  
4. 顯示最終獎金（呼叫 domain）  
5. 發放篩選總覽 + 上季獎金發放兩塊 KPI  

**完成定義**：用固定 fixture 資料，畫面數字與 Phase 1 測試一致。

### Phase 3 — 對齊個人版體驗

- [ ] 搜尋、CSV、再同步、手機卡片、倍率頁、規則頁  
- [ ] RWD／空狀態文案沿用已驗證用語（收款季度、回簽月份統計等）

### Phase 4 — 若選正式多帳號（方案 B）

依序（細節見 spec）：

1. 新表 + RLS 替換  
2. seed ivy + 業務別名  
3. 業務篩選／未歸屬  
4. `/admin`  
5. 訪客試算（若要）  

**完成定義**：業務 A／B 互不可見；ivy 可看全部與掛未歸屬。

### Phase 5 — 下線／雙軌

- [ ] 個人版繼續當「我自己用」或標為 legacy  
- [ ] 資料遷移腳本（若同業務要搬）  
- [ ] 文件：本計畫 + handoff 更新「現行產品是誰」

## 7. 驗收清單（平行版必須通過）

### 計算

- [ ] 回簽 2026-03、未連稅 100000 → 最終 **3500**（3.5%）  
- [ ] 回簽 2026-06、designer、倍率全 1、未連稅 100000 → **4000**  
- [ ] 回簽 2026-06、designer、火箭 2、其餘 1 → **8000**  
- [ ] 缺回簽月份 → 無法計算／不計入可計算總計

### 季度與發放

- [ ] 收款 2026-07 → 收款季 **2026-Q2**  
- [ ] 「8 月發放」含收款 2026-05／06／07，**不含** 2026-08  
- [ ] 收款 2027-01 → 屬 **2026-Q4**；對應公司發放 **2027-02**

### UI 行為

- [ ] 系統日為 8 月 → 預設收款季度 **Q3**  
- [ ] 同時「上季獎金發放」預設波次為 **8 月發（Q2 收款）**  
- [ ] 兩塊數字允許不同，文案需寫清「篩選」vs「公司發放波次」

### 跨季

- [ ] 回簽 Q1 + 收款 Q2 → 金額用舊制；歸在 Q2 收款篩選與 8 月發放
